# Network environments, packet capture, and transport oracles

Research date: 2026-10-01. Scope: externally imposed network conditions for Bow Shock, macOS first and Linux second. This complements [OS input and behavior](os-input-and-behavior.md), [the network observatory](network-observatory.md), and [privacy experiments](fingerprints-and-privacy.md). No upstream tools were installed or run, and no host networking was changed.

The useful design distinction is between changing packet delivery, changing OS connectivity information, and changing what a page observes. All three can be caused outside Chromium, but they are different interventions. A packet shaper can cause a real transport stall without producing an OS offline transition. A native path transition can cause Chromium to react without establishing that a particular origin is unreachable. Privacy benefit is a further experimental claim: this corpus provides mechanisms and measurement patterns, not evidence that random interruptions defeat tracking.

## Mechanisms and the claims they support

| Intervention outside the browser | Direct effect to measure | OS/page offline consequence | Confinement issue |
|---|---|---|---|
| Kernel delay, rate, loss, duplication, reordering | Arrival timing, queue occupancy, received bytes, loss at a controlled peer | An offline event is not implied | Interface, direction, routing, and classifier determine affected flows |
| TCP stream proxy stall/reset | Proxy/client/server reads, connection close/reset | Often a request error while OS remains online | Only connections routed through the proxy; UDP traffic needs another mechanism |
| Controlled DNS failure | Resolver outcome and actual connection attempt | Name failure is not equivalent to link loss | Resolver caches, alternate addresses, and other processes sharing DNS configuration |
| Link/address/route transition | OS interface/path callbacks and live route selection | Chromium response depends on its platform notifier and feature configuration | Shared interfaces and default routes can also affect the agent connection |
| Recorded response replay | Which recorded origin/response was selected and page behavior | Replayed content can continue without Internet connectivity | Replay isolation, origin layout, TLS trust, and matching semantics |
| Passive packet capture | Packets visible at the capture point, capture drops, timestamps | Observes traffic; does not define page or reachability semantics | Interface selection, privileges, metadata and content retention |

The OS notifier and `navigator.onLine` analysis is already in the OS report, including Chromium's Apple path/legacy SystemConfiguration branches and Linux netlink/portal branches. Reuse those reviewed IDs. Do not replace the experiment with synthetic JavaScript online/offline events: that would test a different intervention. Conversely, do not label every dropped-packet experiment “offline.” The matrix is a proposed separation of fault classes and direct oracles, not a claim that every row has been tested on this Mac.

## macOS mechanisms and a concrete scoping failure

Apple's released XNU contains a dummynet queue/delay implementation. The reviewed `bsd/netinet/ip_dummynet.c` checks a configured loss probability, accounts packet bytes for bandwidth credit, and stages packets with an output deadline. This is substantive outside-browser packet handling. The source also emits typed dummynet configuration events; that is not proof that `NWPathMonitor`, Chromium, or a page will report offline. Runtime capability and notifications must be checked on the intended macOS release. [Pinned Apple implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/netinet/ip_dummynet.c).

Comcast is a particularly useful negative reference. Its macOS backend enables PF, reloads `/etc/pf.conf` with an added anchor, routes interface input through fixed pipe 1, and configures that pipe. Teardown reloads `/etc/pf.conf`, disables PF globally, and flushes dummynet globally. This does not preserve unrelated live firewall/pipe state. Its IP/port “target” arguments appear inside dummynet `mask` configuration rather than PF traffic-selection rules. Those mask fields partition flows; they do not establish that other destinations bypass shaping. This is a source-review finding, not an executed failure. [Pinned backend](https://github.com/tylertreat/comcast/blob/145d02155cffc03bb4ed878c9d6441dc49f3cdaa/throttler/pfctl.go).

The accompanying tests record generated command strings and compare them with expected strings. They help study parser/command regressions but do not demonstrate selective kernel behavior, preservation of another owner's PF rules, or transport recovery. Bow Shock should learn from that missing oracle before considering any native network helper. [Pinned tests](https://github.com/tylertreat/comcast/blob/145d02155cffc03bb4ed878c9d6441dc49f3cdaa/throttler/pfctl_test.go).

The author paper *Dummynet Revisited* makes the classifier/mask distinction explicit: a pipe represents queue capacity, bandwidth, and propagation delay; classifier rules choose the packets entering it; masks group packets into dynamic flows. It argues for composing queue and traffic mechanisms where losses depend on congestion rather than imposing unrelated loss traces. Its precision and MAC-emulation limitations remain relevant questions; its 2009 draft is historical evidence, not a current macOS command contract. [Author draft associated with CCR 2010](https://docenti.ing.unipi.it/l.rizzo/papers/20091201-dummynet.pdf).

SystemConfiguration's own reachability contract says it describes whether a packet can leave the local computer, without guaranteeing remote receipt. Unscheduled checks can be optimistic when a default route exists and DNS is still needed. Thus DNS failure, blackholed delivery, and local path availability need separate observations. Apple's configd source includes `SCNetworkReachability.c`, the documented header, `sctest/SCTestReachability.m`, and `tests/ReachabilityTester.c` for further study. [Pinned contract](https://github.com/apple-oss-distributions/configd/blob/585b7f2fca293f4642d21d15c5daf187f63c4796/SystemConfiguration.fproj/SCNetworkReachability.h).

Apple's WWDC25 native examples add a useful client-side reference: connection preparation, waiting, readiness, failure, and cancellation are explicit states; interface policy can constrain an individual connection. These are native application APIs and do not demonstrate global packet shaping. A future operator-facing monitor can distinguish observed path changes from endpoint errors and from deliberately imposed faults. The linked peer-to-peer sample is still a lead because the web reader returned a JavaScript shell and its source archive was not resolved. [Official presentation and code snippets](https://developer.apple.com/videos/play/wwdc2025/250/).

## Linux shaping and topology references

Netem offers delay distributions, approximate correlation, burst-loss state models, duplication, corruption, reordering, rate, slotting, and seeds. Its own manual warns about timer granularity, unexpected interactions with other qdiscs, and TCP Small Queues: realistic TCP performance measurements require attention to receiver-side placement. A seed controls random choices, not thread scheduling, traffic arrival order, or the entire experiment. Begin with a simple explicitly located queue before attributing results to a complex impairment model. [Pinned upstream manual](https://github.com/iproute2/iproute2/blob/ac0b672924c8993a2da2cb9b6f97908967095a97/man/man8/tc-netem.8).

`iproute2` contains the netem command parser and namespace tooling, not Linux's `sch_netem` kernel implementation. `tcconfig` wraps `tc` with interface, incoming/outgoing, address/network, port, and container-veth options plus current-configuration output. That is a study aid for configuration representation, not proof of isolation. Its documented delete-all operation is scoped to an interface, which can still have unrelated users. [tcconfig README](https://github.com/thombashi/tcconfig/tree/ee55d275603f2cb8c10c3fbe84989ea71149f5de).

Mahimahi supplies the closest architectural precedent for running an unchanged browser within a controlled network environment. Its composable Linux namespace shells separate host traffic, preserve multiple server endpoints during HTTP replay, and offer fixed-delay and trace-driven delivery opportunities. Replay uses response matching heuristics and HTTPS recording intercepts TLS, so this is not passive capture or exact server execution. The original paper evaluates historical protocol configurations; it does not establish modern HTTP/3 support. Its arbitrary-topology limitation is also explicit. Study its isolation and composition before adopting its implementation. [Architecture and replay sections](https://www.usenix.org/system/files/conference/atc15/atc15-paper-netravali.pdf).

Mininet's original paper demonstrates lightweight Linux network namespaces and virtual links with real applications, but calls out shared-kernel and scheduling constraints that weaken performance fidelity under load. Use it for controlled topology and routing questions; do not assume emulated performance equals separate physical hosts. CORE adds topology construction, scripting, service configuration, and connection to live networks. Its README and node layout were reviewed; its radio/routing integrations were not evaluated. These are Linux research environments rather than native macOS equivalents. [Mininet paper](https://conferences.sigcomm.org/hotnets/2010/papers/a19-lantz.pdf), [CORE reference](https://github.com/coreemu/core/tree/a5cff7f99e02a2acf629e19c307926c62c818fd6).

For Bow Shock, a dedicated window alone does not identify a networking authority boundary. Network services and sockets belong to processes and interfaces; multiple windows may share them. The proposed narrow experiment must identify the complete browser process group and path, keep the agent/control channel outside that path, and distinguish namespace-local interface changes from any shared host connectivity portal. An external emulator/gateway also deserves consideration for testing macOS without rewriting host-wide rules, but that is a design lead rather than a selected deployment arrangement.

## Stream faults, capture, and direct test oracles

Toxiproxy is useful when a controlled service can be reached through a TCP proxy. Its timeout toxic consumes incoming stream chunks without forwarding them and can close the connection; timeout zero leaves the stream blocked until other lifecycle events intervene. Removing the toxic closes the connection in the reviewed implementation. This differs materially from a kernel dropping packets while TCP retransmits. The tests first establish bidirectional byte delivery, then check removal yields EOF at both ends and that removal does not hang in a composed latency/timeout case. [Implementation](https://github.com/Shopify/toxiproxy/blob/40f7fd31bee529d824116bd2a11a9e3425e904ec/toxics/timeout.go), [direct connection tests](https://github.com/Shopify/toxiproxy/blob/40f7fd31bee529d824116bd2a11a9e3425e904ec/toxics/timeout_test.go).

Packetdrill offers a stronger transport oracle than “the command succeeded.” Its scripts combine timed socket calls and expected packets against the actual OS stack. Current `run_packet.c` maps live values into script space and checks headers, TCP options, payload, checksums, and packet timing. Some checks can be relaxed or converted into warnings, so those flags are part of the test's claim. The paper and README describe local TUN and remote wire configurations on supported Linux/BSD systems; macOS support was not established. It is a reference for precise transport assertions, not a page automation or fingerprint experiment. [Paper](https://www.usenix.org/system/files/conference/atc13/atc13-cardwell.pdf), [pinned verifier](https://github.com/google/packetdrill/blob/83f72d3f9085d0e26eb4d206fe4d7cfab5b6d872/gtests/net/packetdrill/run_packet.c).

Libpcap, tcpdump, and selected Wireshark capture files provide portable capture and offline inspection. Capture statistics require care: libpcap's counts differ by platform; `ps_drop` concerns capture-buffer loss, and a zero `ps_ifdrop` can mean the statistic is unavailable. Live statistics are not stored in ordinary pcap savefiles. Therefore a missing packet in a capture is not automatically an injected network loss. [Pinned statistics contract](https://github.com/the-tcpdump-group/libpcap/blob/e2fe69377b84cf5e963b54946cb616cfbc4a76d4/pcap_stats.3pcap).

Wireshark documents that timestamp resolution and accuracy differ and depend on the capture system; it displays timestamps supplied through the capture library. Host capture can also observe packets before hardware checksum completion and segmentation, producing misleading checksum errors or packet sizes. Record capture position, timestamp source, offload context, and drops before comparing with emulator timing. Passive encrypted captures do not by themselves reveal page semantics or TLS plaintext. [Timestamp guide](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvTimestamps.html), [checksum/offload guide](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvChecksums.html).

Iperf3 is a controlled transport measurement reference for throughput, UDP loss/jitter, reverse direction, and machine-readable output. It requires a chosen peer and consumes the path it measures. Its result is not the page's experience; running it concurrently changes traffic contention. Use it in a calibration experiment when the intended claim is about transport delivery. [Official invocation guide](https://software.es.net/iperf/invoking.html).

## Proposed evaluation and remaining questions

First define a single mechanism and a controlled endpoint. For fixed-delay or rate experiments, measure receive timing and useful received bytes rather than generated command strings. For intentional drops, distinguish shaper/receiver observations from capture-buffer loss. For link/path experiments, pair native path notifications with actual endpoint attempts and page event/error observations. For DNS faults, distinguish uncached name resolution failure from failure of an already connected socket. These are separate direct fault oracles, with no extra layer whose only purpose is validating another receipt.

Confinement is an independent fault class. A future experiment should include an unaffected control connection representing the agent channel, a pre-existing unrelated configuration, and a controlled interrupted browser connection. Restore only experiment-owned resources even after partial setup failure or cancellation. The required property is preservation of other owners' state, not merely absence of a crash. Comcast's command tests do not supply that evidence.

The privacy study then needs a stated adversary observation model, task utility, and a measured before/after comparison. Outside-browser perturbations may alter request timing, connection reuse, retries, or page interaction timing, but stable identifiers can remain and repeated unusual patterns may themselves be observable. Those possibilities require experiments; this network corpus makes no anonymity, indistinguishability, or site-acceptance claim.

Deferred acquisition/read gaps: the original 1997 dummynet author copy is PostScript, which the web reader could not parse; the institutional abstract and the later author draft were reviewed instead. The BPF paper is a scanned PDF without extracted text and is retained as a reading lead; no historical speedup claim is used here. Apple peer-to-peer sample download/source remains unresolved. Apple network_cmds was already in the earlier catalog and its retry status belongs to the shared ledger. The three large repositories' recursive tree requests were truncated by transport errors, so exact selected paths were verified through bounded directory listings instead. No runtime tests, current macOS binary/source equivalence, browser process-path confinement, or empirical tracking outcome has yet been established.
