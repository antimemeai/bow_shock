# Preview and dated recipes

The operator specified the practical implementation standard: a naive extraction
and one round of tweaks are step zero. If those do not work, operator and bot
inspect the actual page and adjust until useful; save the successful page-type
approach as a dated recipe. The product needs a preview renderer where the actual
attempt can be evaluated. This replaces any implication that we first need a
generic collector or extractor that understands every website.

Read the active native panel, Blackbird connection API and CMake target. The
application currently has only a plain conversation transcript and saved-reading
paths; no extraction result model, preview renderer or recipe storage is wired.
The complete archives and coding-agent file tools are available inputs for a
first pass. The preview must be a separate view of the actual structured result,
with the same attempt inspectable by operator and bot.

Recorded the loop and first implementation unit in
`docs/plan/extraction-preview-recipes.md`; updated product intent, current visit
and integration plans, README and AGENTS. No universal page model, new dependency
or rendering implementation was silently selected. Recipes preserve reusable
instructions and dated revisions separately from per-visit extracted values.
One tweak bounds initial automatic iteration, never harvesting or directed
operator/bot work.
